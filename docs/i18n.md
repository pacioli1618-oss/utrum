# Internationalization (i18n)

Utrum speaks **pt-BR** (default), **es** and **en**, using [`next-intl`](https://next-intl.dev) 4 with Next.js 16 (`cacheComponents` on).

## How the locale is picked

1. The `UT_LOCALE` cookie, set when the person switches language.
2. Without a cookie, the browser's `Accept-Language` header.
3. If nothing matches, `pt-BR`.

**URLs never carry the locale** (`localePrefix: 'never'`). The list link, `/l/<slug>`, is the same for everyone, and each person sees the UI in their own language. Under the hood, `src/proxy.ts` rewrites the request to `/<locale>/l/<slug>`. The locale is then a *root param* (`next/root-params`), so pages stay static and cacheable: no page reads `headers()` or `cookies()`.

## Where things live

| Path | What it is |
| --- | --- |
| `src/i18n/locales.ts` | Locales, default locale and each language's name. **Single source.** |
| `src/i18n/routing.ts` | next-intl routing config (no prefix, `UT_LOCALE` cookie) |
| `src/i18n/request.ts` | Loads the current locale's messages and sets the default time zone |
| `src/i18n/navigation.ts` | Locale-aware `Link`, `useRouter` and `redirect`. Use these, not the `next/*` ones. |
| `src/i18n/numbers.ts` | `useFormatPercent()` for progress and agreement |
| `src/i18n/errors.ts` | Turns `ut_*` RPC error codes into translated messages |
| `src/proxy.ts` | Detects the locale and rewrites to `/<locale>/…` |
| `src/app/[locale]/` | Every page. The root layout lives here. |
| `src/types/next-intl.d.ts` | Typing: an unknown key or a missing argument fails the build |
| `messages/<locale>.json` | The copy. `pt-BR.json` is the source. |
| `scripts/check-messages.mjs` | `npm run i18n:check`: keys, ICU syntax and arguments |

## Rules for writing copy

- **Always ICU, never concatenation.** Write `"{count, plural, one {# pessoa} other {# pessoas}}"`, not `n + " pessoas"`. Word order changes between languages.
- **User content is never translated.** List title, criterion, items and names appear as written. The ready-made criteria are suggestions: once picked, the question is stored as text in the creator's language.
- **Neutral Latin American Spanish**, using "tú".
- **Naming** of namespaces and keys follows `docs/conventions.md`, section 8.

## What the list stores

`utrum.lists` has `locale` (the creator's language, used for link previews). `ut_create_list` takes `p_locale`.

## Adding a locale

1. Add the code to `locales` and `localeNames` in `src/i18n/locales.ts`.
2. Copy `messages/pt-BR.json` to `messages/<new>.json` and translate it.
3. Run `npm run i18n:check` and `npm run build`.
4. Add the code to the `check (locale in (...))` on `utrum.lists` in a new migration.

## Known limits

- **Server Actions and Route Handlers** have no root params. Pass the locale explicitly there: `getTranslations({locale, namespace})`.
